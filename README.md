# Team 3 GitHub Rules

## General Guidelines

- **Do not commit directly to the `main` branch.**
- **Do not commit directly to the `main` branch.**
- **Do not commit directly to the `main` branch.**

- When your work is finished, **create a pull request to the `launcher/main` branch** for review and merging.
- **Create your own branch** for your game or feature and work there. **Branch names should follow the format `dev/yourname_functionname` (e.g., `dev/oivia_TetrisMath`).**
- **Commit regularly** on your own branch to maintain version control and allow for easy reverts if needed.
- Feel free to **add or edit these rules** as the project evolves.

## Additional Suggestions
- Keep commit messages clear and descriptive.
- I will review all pull requests before approving, do not approve on your own will.
- Communicate with the team about major changes on Microsoft Teams or F2F.
- Keep your branch up to date with the latest changes from `launcher` or `main`.
- Keep the design and code style consistent with the rest of the project.
- Use descriptive names for variables, functions, and classes.
- Write comments and documentation properly.
- Test your code thoroughly before submitting a pull request.
